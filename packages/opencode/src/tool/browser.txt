Operate the OpenCode Browser surface. Use this when the task needs a real interactive browser for public websites, login-heavy flows, DevTools-style inspection, Browser Use coordination, Playwright CLI automation, element highlighting, network/console inspection, or screenshots. The visible Browser tab is the shared Chrome/Chromium surface for Alfonso and model browser tools.

Use the `preview` tool instead for controlled/internal/local URLs, OpenDesign embeds, hosted dashboard previews, and file/project app surfaces where the user expects a lightweight in-OpenCode viewer.

Each OpenCode session gets its own browser session name and persistent profile. Start with action=open for a new session, then use actions like goto, snapshot, click, click-point, type, press, scroll, fill, highlight, screenshot, requests, console, or tab-list. Screenshot results are attached back to the conversation when a PNG is produced.

The Browser tab uses a real Chrome/Chromium instance with CDP control. The visible panel now prefers the lightweight interactive noVNC viewer for manual use, while CDP remains the primary tool/control path for navigation, screenshots, selectors, DevTools-style data, Browser Use, and Playwright tooling. The screenshot stream remains available as a fallback and annotation surface. Avoid entering or exposing secrets unless the user explicitly authorizes it. The dedicated live Chrome profile can persist state; extensions and password managers remain separate explicit opt-ins.
